# Threat model

What the workbench service protects, from whom, and what is still open. Written for the 1.1.0 code;
nobody independent has reviewed it. The lab's own research scope is in [SECURITY_SCOPE.md](../SECURITY_SCOPE.md).

## What it protects

| Asset | Where it lives |
|---|---|
| Cases: frozen intents, both paths' SQLite effects, findings, reduced reproductions, reports, hash manifests | the data directory (`/data` in the image) |
| Browser-run evidence (Chrome traces, screenshots) | CLI output folders on the workstation |
| API keys | callers hold the key; the server holds only SHA-256 hashes |

## Trust boundaries

1. **Browser or script → server.** Bodies are parsed with a strict JSON reader (no duplicate keys,
   bounded size) and validated before a run.
2. **Server → local Chrome.** Browser jobs launch Node and Chrome against `127.0.0.1` only.
3. **Server → filesystem.** Case IDs are generated by the server and resolved inside the data directory.

## Threats and what stops them

| Threat | Mitigation | Residual risk |
|---|---|---|
| Another site's page drives the workbench or its browser runner (CSRF, DNS rebinding) | Exactly one `Host` header, loopback or listed in `ALLOWED_HOSTS`; a single `Origin`, which must match; JSON only | — |
| Someone on the network reads cases, runs experiments or starts Chrome | Hashed API keys with roles; production refuses to start without them; browser routes are off whenever keys are configured | Every key sees every case (single tenant) |
| Flooding or a long run ties up the server | 1 MiB bodies (8 MiB for browser evidence) with exactly one Content-Length, no chunked bodies, one experiment at a time (409), rate limit per keyed or remote client, 15 s socket timeout | A key-less loopback workbench is not rate-limited (one person's workstation) |
| A request escapes the runs directory | Server-generated case IDs; path checks in case lookup | — |
| A bundle is altered after export | SHA-256 manifest checked by `verify` | The manifest is unsigned |
| Content leaks into logs | Access logs are JSON with method, route, status and user only | — |

## Not covered

- Multi-tenant isolation between keys.
- Browser automation through the web service (it is a workstation feature).
- TLS (terminate it at the ingress).
